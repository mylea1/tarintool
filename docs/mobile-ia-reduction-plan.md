# KILO 移动端信息架构减法改版

日期：2026-08-03  
规划：Sol  
实现：Luna Worker  
状态：已批准执行

## 问题判断

目标用户是在健身房单手操作手机的规律训练者。当前最大问题不是功能不足，而是七个底部入口、训练页长列表、官方多周计划和历史数据同时争夺注意力，导致用户很难快速完成“选一节训练并开始”的主任务。

用户当前已经通过两张真机截图提供了明确证据：底部入口过多；模板编辑器在窄屏发生 Flutter overflow；官方计划占据过多首屏；模板卡片的更多菜单不如显式按钮直观；进步数据只有单值，没有解释价值。

## 产品目标

- 一级导航从 7 项收敛为 5 项，降低选择成本。
- 训练页首屏只推动一个动作：选择自己的计划或新建训练。
- 历史、官方计划、计划详情和进步分析按需打开，不在主页面铺开。
- 所有官方计划都变成单日训练模板，不表达“4 天 / 12 周”等周期承诺。
- 进步数据从孤立数字变成趋势、训练量和动作表现的可解释视图。

## 方案比较

### A. 只隐藏部分卡片

改动最小，但底部导航和页面职责仍然重复，无法解决根因。

### B. 一级入口合并，二级顶部切换（采用）

底部保留主页、训练、动作、AI、我的。训练内切换计划/记录；AI 内切换问答/动作识别。复用现有页面与控制器，风险可控，同时明显减少首屏信息量。

### C. 全面重写为训练任务流

长期结构最纯粹，但会重写大量稳定状态和测试，当前阶段成本与风险过高。

## 导航结构

```text
底部导航
├─ 主页
├─ 训练
│  ├─ 计划
│  └─ 记录
├─ 动作
├─ AI
│  ├─ 问答
│  └─ 动作识别
└─ 我的
```

实时训练仍是训练入口上的独立沉浸状态，不占用一个新的底部导航项。

## 训练与模板

- 训练顶部使用清晰的分段导航“计划 / 记录”。
- 计划页首屏保留“新建计划”和我的训练计划列表。
- 删除文件夹筛选、分类与“新建文件夹”。现有数据中的 folder 字段可暂时保留以兼容旧数据，但不再作为 UI 主路径。
- “空白训练”统一改名为“新建训练”。
- 模板卡片右侧的竖向更多菜单改为有文字的“编辑”按钮。
- 官方计划缩成一条次级入口“使用官方计划”。点击后打开计划列表弹窗。
- 每个官方计划只代表单日训练，显示训练部位、动作数和预计时长。
- 点击官方计划先打开二级详情弹窗，列出动作、组数、次数和休息，再允许“使用此计划”或“开始训练”。
- 模板编辑器底部固定显示“保存”按钮。保存后关闭并提供即时反馈。
- 组别编辑行必须自适应：窄屏采用分行或 Wrap，不再把组别类型、重量、次数和删除按钮硬塞进同一行。

## 记录

- 日历继续作为记录主页核心。
- 首页历史记录仅显示最近 3 条。
- “查看全部”打开可滚动历史弹窗。
- 点击任意历史记录打开详情弹窗，显示训练动作以及每组的组别类型、重量、次数和组间歇。
- 历史详情必须支持长动作名、200% 字体和空记录状态。

## AI 与动作识别

- AI 页顶部使用“问答 / 动作识别”切换。
- 问答仍保持简洁对话和历史抽屉。
- 动作识别复用现有上传、分析和报告状态，不重复底部入口。
- 当主页进步项需要跳转到识别时，应直接打开 AI 页的“动作识别”标签。

## 主页进步

- 主页保留 2 至 3 条摘要，不继续增加指标卡。
- 点击摘要或“查看趋势”打开进步分析弹窗。
- 弹窗使用真实组件绘制：训练量折线/面积趋势、关键动作近期表现、总训练量、有效组、变化率和文字解释。
- 视觉可以更有冲击力，但颜色仍遵守 KILO token：钴蓝为主，青柠只表达正向进展，橙色只表达注意。
- 图表必须包含轴标签或数值提示，不能只靠形状表达。

## 验收标准

- 底部导航固定为 5 项；训练/记录和 AI/识别分别通过顶部切换访问。
- 320、375、414 px 宽度和 200% 字体下无横向 overflow。
- 模板编辑器没有红色 `RenderFlex overflowed` 提示。
- 所有官方计划均为单日，详情中可以查看动作明细。
- 新建/编辑模板有显式保存按钮和保存反馈。
- 历史默认最多 3 条；全部历史与单次详情均可打开。
- 主页进步点击后显示至少一种趋势图和可解释指标。
- 原有实时训练、日历、AI 对话和识别状态不回退。

## 商业判断

这次改版最可能提升“从打开训练页到开始第一组”的完成率。负责推动该指标的关键设计是五项底部导航、训练页首屏只保留个人计划和新建训练，以及把官方计划与历史详情后置到弹窗。
