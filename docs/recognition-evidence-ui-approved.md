# 动作识别证据报告界面设计

状态：已确认
确认时间：2026-08-23
适用页面：Flutter 动作识别结果页

## 用户问题

当前报告把“目标锁定、骨骼追踪稳定、时间提示数量”和“播放骨骼证据”放在较高视觉层级，但这些是系统状态，不是训练者最想知道的答案。事件列表只有“下拉行程”“肘部路径”等短标签时，用户仍需要自己猜测问题含义和调整方法。

## 已确认的设计原则

1. 结果页使用用户选定的“动作轨迹”布局骨架，但继承形域现有的暖橙色 Material 3 色调。
2. 首屏和事件列表都以“文字说明 + 对应时间的骨骼标注图片”为主要输出。
3. 每个事件直接回答四件事：发生时间、发现了什么、这意味着什么、下一组怎么调整。
4. 不显示目标锁定、骨骼追踪稳定、时间标记数量等系统状态概览。
5. 不显示“播放骨骼证据”大按钮，也不解释用户可以点击图片。图片仍可点击放大；存在完整骨骼视频时，通过点击顶部媒体进入，不在页面中主动宣传。
6. 不使用“第几次动作”或动作次数描述，只使用视频时间。
7. 系统测量值作为解释证据出现，但不能替代自然语言结论，也不能包装成医学判断。

## 方案取舍

### 方案 A：只扩写现有事件卡片

改动最小，但仍保留旧报告的大卡片、指标和系统状态层级，不能解决信息焦点错误。

### 方案 B：证据优先的动作轨迹报告（已选择）

顶部展示当前证据帧和视频时间，下方按时间排列事件。每个事件直接展示详细文字和骨骼标注图。系统状态与完整骨骼视频降为隐式交互。

### 方案 C：时间轴列表跳转独立详情页

适合事件很多的长视频，但当前 45 秒以内的识别视频会产生额外跳转，用户需要来回切换才能比较问题。

## 页面结构

1. 标题：动作轨迹。
2. 副标题：动作名称和推荐机位。
3. 顶部证据媒体：默认显示第一个时间事件的骨骼标注图；可横向切换事件或点击下方事件定位。
4. 结果导语：只说明本次需要关注的时间点，不展示系统内部置信度和跟踪状态。
5. 事件详情：时间、完整问题名称、发现说明、含义、下一组调整、骨骼标注图。
6. 本组建议：保留有用的教练文字，但去除重复事件标签和技术状态说明。
7. 保存提示：保留为低优先级文本操作。

## 成功标准

- 用户无需点击即可理解“下拉行程”和“肘部路径”的具体含义。
- 每个事件都有清楚的自然语言说明和对应骨骼图。
- 页面中不出现动作次数、目标锁定状态、骨骼追踪状态、时间提示数量概览或大号播放骨骼视频按钮。
- 320、375、414 像素宽度和 200% 文本缩放下无水平溢出、文字遮挡或不可点击内容。
- 图片加载、加载失败、无事件、无 AI 建议和完整骨骼视频存在/不存在均有可用状态。

## 商业判断

这次改版最可能降低错误理解和重复上传率。推动指标的关键不是更强的视觉装饰，而是把每个问题的时间、解释、调整建议和骨骼证据放在同一个阅读单元中。
