# 真实业务逻辑审计（2026-09-05）

## 结论

本次审计以正式 Flutter 客户端 `mobile/` 和业务后端 `backend/` 为范围。`web-prototype/` 在项目 README 中被明确标注为使用 `localStorage` 和 Mock API 的交互原型，因此不把它的模拟数据列为正式客户端缺陷。

AI 定制计划失败的直接原因不是 DeepSeek 不可用，而是设备端工具结果与后端大小限制不一致：客户端最多会返回 20 次训练、每次 12 个动作、每个动作 12 组的结构化数据；后端却在把内容裁剪给模型之前，先拒绝了超过 12,000 字符的请求，返回 `ai_tool_result_too_large`。

修复后采用双层保护：

- 客户端在传输前把单个超大工具结果压缩到 10,000 字符以内，兼容尚未升级的服务端。
- 后端允许接收最多 256,000 字符的设备结果，但送入模型上下文的内容始终限制为 12,000 字符，避免上下文失控。
- 超过 256,000 字符的异常请求仍返回 `413 ai_tool_result_too_large`。

## 已确认的空壳或不完整业务

| 优先级 | 功能 | 现状证据 | 判断与建议 |
| --- | --- | --- | --- |
| P0 | Google 登录 | 登录页展示 Google 入口；`AccountService.loginWithGoogle()` 固定返回 `serviceNotConfigured`。后端已有 `/v1/auth/google` 验证接口，但 Flutter 没有原生 OAuth、ID Token 获取和提交链路。 | 这是明确的“有按钮、无客户端业务逻辑”。在接入 `google_sign_in`、平台 OAuth 配置和真机回归前，应隐藏该入口或标注未开放。 |
| P0 | “通知反馈”开关 | `androidNotifications` 只在控制器声明一次，并只被个人页开关读取和修改；没有持久化、权限申请、计划提醒调度或通知服务调用。 | 当前开关只改变当次内存中的文字和状态，不会真正开启/关闭训练提醒。应接入本地通知权限与调度后再保留，或暂时移除。 |
| P1 | 服务端推送注册 | 后端有 `/v1/push-tokens` 存储接口，但 Flutter 没有调用方，也没有 FCM/APNs token 获取；后端未发现实际推送发送器。 | 属于孤立的后端骨架，不是完整推送业务。需要补齐客户端注册、失效 token 清理、发送任务与送达监控。 |
| P1 | 饮食“AI 建议”降级 | 登录用户会真实请求 Coach；请求失败后异常被静默吞掉，并生成本地规则建议，界面仍显示为 AI 建议。 | 功能可用但来源表达不真实。应显示“智能规则建议（AI 暂不可用）”并提供重试，避免把确定性本地规则冒充远程 AI。 |
| P1 | 头像跨设备 | 用户名会通过 `/v1/me/username` 写入后端；头像只保存本机文件路径 `avatarPath`，没有上传、远端 URL 或云同步。 | 本机修改真实有效，但换设备、卸载或本地文件丢失后头像无法恢复。若产品承诺账号头像，应增加媒体上传和账号资料字段。 |

## 已核实为真实链路，不应误判为 Mock

| 功能 | 核实结果 |
| --- | --- |
| 手机号登录 | 客户端请求、验证码验证、安全会话恢复和后端 PNVS/数据库链路均存在；不是本地假登录。 |
| Apple 登录 | Flutter 使用原生 Sign in with Apple，服务端校验 Apple 身份令牌；仍依赖 Apple 控制台和服务端凭据配置。 |
| 微信/支付宝会员支付 | 客户端能力探测、服务端固定金额下单、签名回调和幂等授予均存在；未配置商户环境时主动禁用，不是假成功。 |
| 云同步 | Flutter 有拉取/写入逻辑，后端 `/v1/sync` 有用户隔离和版本冲突控制。 |
| 好友、训练动态、点赞与表情 | 客户端和后端均有真实接口及权限边界；`PopupMenuButton` 内部 `onPressed: null` 的按钮只是菜单的视觉 child，不是死按钮。 |
| AI 问答、AI 计划、训练完成评价 | 均调用真实 Coach 接口，并有会话、额度和失败回滚；本次修复的是工具结果续传边界。 |
| 动作识别和饮食图片识别 | 均有真实 HTTP/任务接口；服务未配置时返回明确错误，不生成伪造识别结果。 |
| 官方训练计划 | 计划目录由后端 `/v1/training/official-plans` 提供，移动端只负责拉取、缓存和展示。 |
| Apple Watch / Android 训练通知桥 | 原生桥代码和状态同步存在，不是 UI Mock；Apple Watch 仍需 macOS 配对模拟器或真机完成签名与连接验证。 |

## 自动化验证

- 后端完整测试：60/60 通过。
- `mobile/test/ai_api_test.dart`：覆盖小结果保持结构、超大结果传输压缩，定向测试通过。
- Flutter 全量测试当前有 2 个与本次 AI 改动无关的失败：320dp 训练组行溢出，以及删除组测试点击到禁用按钮。它们发生在工作区中同时存在的 `main.dart`、`controller.dart`、`widget_test.dart` 等未提交改动上，本次没有覆盖或提交这些文件。

## 建议处理顺序

1. 先部署本次后端修复，使已安装版本立刻停止收到 `ai_tool_result_too_large`。
2. 发布包含客户端压缩保护的新版本，防止旧服务端或代理限制再次导致同类故障。
3. 隐藏或完成 Google 登录，并修正“通知反馈”开关，这是用户最容易直接遇到的两个空壳入口。
4. 明示饮食建议的本地降级来源，再补齐头像跨设备和推送全链路。
