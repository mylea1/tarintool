## 6. 容易犯的错误与正确做法

| 容易犯的错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 把 GitHub 推送、服务端部署和 App 更新当成同一件事 | 用户安装的旧 App 不会自动获得移动端修复 | 分别说明代码提交、服务器版本和 APK/IPA；移动端改动必须重新构建并安装 |
| 从错误分支或共享 `app-debug.apk` 交付 | 用户再次安装带 3D/附近社交的错误包 | 只从 `master` 的确定提交构建，文件名包含 `master`、短提交号和 API，提供 SHA256 |
| 构建时遗漏 API 地址 | AI、好友、会员或识别访问错误环境 | 使用 `--dart-define=KILO_API_BASE_URL=https://api.kilostrength.cn` |
| 出现服务不可用就同时重启所有服务器 | 造成额外中断，甚至影响企业微信机器人 | 先区分客户端 Token、业务 API、上游 AI、Worker 和网络入口；只更新发生源码变化的服务 |
| 客户端显示已登录但 Token 仅存在内存 | 冷启动后 AI、好友、会员、识别全部像“服务不可用” | 保持 `flutter_secure_storage` 会话恢复；Token 绑定账号、API origin、过期时间，401 时清除并提示重新登录 |
| 把所有错误都映射为“AI 服务暂时不可用” | 用户无法判断是未登录、额度、超时还是服务器故障 | 分别显示登录过期、非会员/额度、网络错误、超时、上游不可用；服务端记录可追踪错误但不泄密 |
| AI 自行推断当前日期 | “昨天”被解析成错误月份或年份 | 请求中传入客户端绝对日期、时区和目标训练日期；服务端提示词以这些字段为准 |
| 休息计时每秒递减、锁屏不保存截止时间 | iOS 锁屏或系统杀后台后计时停住、少一分钟 | 保存绝对截止时间；恢复时用当前时间重新计算，不依赖定时器累计 |
| 用计划名或整次训练查找“上次重量” | 同动作换计划后带入错误或找不到历史 | 按稳定动作 ID 查找最近完成记录；PR 只与用户本人同动作历史比较 |
| 为精简动作直接删除 1324 条目录数据 | 老训练记录无法解析、图片和动作错配 | 完整 `catalog` 保留历史兼容；`selectableCatalog` 负责隐藏无效/停用动作 |
| 动作识别选择器直接使用整个动作库 | 用户可选择 Worker 根本不会识别的动作 | 识别动作只来自 BetterCoach/Worker 的能力白名单 |
| 识别结果展示置信度、算法术语或对无效视频乱夸 | 用户认为产品不准确且推卸责任 | 只给动作质量、问题、改进方法和时间证据；无可靠目标或非目标视频应明确无法评价 |
| 小屏只缩小触控区域 | 难点按且不符合可访问性 | 缩小视觉图标和留白，但保留约 44dp 触控目标；检查 320dp 和 200% 字体缩放 |
| 不按指定互动 SVG 使用人体图 | 肌群显示不可点、与设计和数据映射不一致 | 以 `docs/ai-training-muscle-selector-files.md` 和 `assets/muscle-selector/` 为唯一来源 |
| 直接升级到依赖最新版 | 可能提高 compileSdk/Xcode 要求并破坏现有构建 | 先核对项目工具链；例如安全存储最终使用兼容的 10.x，而不是要求 compileSdk 37 的 11.x |
| Codemagic 多行命令缺少续行符 | `--dart-define` 被当作独立命令，IPA 构建返回 127 | 保证 Flutter 命令与参数属于同一 shell 命令；同时为 Runner 和 Live Activity Extension 配置签名 |
| 清理脏工作区或覆盖其他会话修改 | 丢失用户/其他任务文件 | 先检查 `git status`，只提交本任务文件；禁止 `git reset --hard`、破坏性 checkout 和无依据清理 |
| 依赖下载反复使用不可用源 | 构建长时间卡住 | Python 优先中科大 PyPI；npm 中科大旧代理已停止，按项目现有配置使用 npmmirror；Flutter 沿用项目可用镜像 |

## 8. 发布和部署规则

1. 修改前检查 `git status`、当前分支和 `origin/master`；有远端新提交时安全整合，避免覆盖用户改动。
2. Git 网络失败只做少量确认，随后继续本地实现和测试，不得反复卡死；不要猜测远端状态。
3. 每次修改都追加到 [近期修改与发布记录](./recent-change-history-2026-08-20-to-2026-08-24.md)。
4. 默认提交并推送 `master`，但只提交本任务文件；不创建 PR，除非用户改变要求。
5. 只有服务端源码变化才部署相应服务器：
   - `backend/` 变化：更新阿里云业务 API，并做本机与公网健康检查；
   - `gpu-worker/` 或 Worker 镜像变化：等待 GitHub Actions/GHCR 成功后更新腾讯云 Worker，并做真实识别冒烟；
   - 仅移动端或文档变化：不要无意义重启服务器；
   - 企业微信机器人始终保持隔离。
6. 继续保持当前 Cloudflare/域名链路，除非用户明确批准改变。
7. Android 包从确定的 `master` 提交构建，并传入：

   ```text
   --dart-define=KILO_API_BASE_URL=https://api.kilostrength.cn
   ```

8. APK 文件名必须带分支、提交号和 API 标识，并报告绝对路径、版本、大小和 SHA256。
