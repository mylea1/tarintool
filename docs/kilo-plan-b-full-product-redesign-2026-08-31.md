# KILO B 方案：官网、社交、饮食与主题完整重构

状态：APPROVED

日期：2026-08-31

## 目标

在不维护旧 `web-prototype` 的前提下，新建只承担产品介绍与下载的正式官网；同时把现有 Flutter 客户端升级为可发布训练动态、查看好友互动、通过多张食物照片自动生成营养候选、跨日期回看训练与饮食、在应用内阅读图文手册，并使用稳定 Android 发布签名的完整产品。

## 用户与核心路径

主要用户是在健身房单手记录力量训练、希望快速回看进步并获得营养辅助的年轻训练者。

核心路径：

1. 开始并完成训练。
2. 保存训练记录，并选择是否发布给好友。
3. 好友查看训练动态、点赞或发送限定表情评论。
4. 用户上传一张或多张食物图片，系统自动生成热量和三大营养素候选。
5. 用户通过统一日历查看同一天的训练和饮食时间轴。
6. 新用户通过应用内图文手册快速理解主要功能。
7. 官网访客理解产品并下载对应平台安装包。

## 产品边界

- 好友动态仅展示用户主动发布的训练快照，不公开训练备注、身体资料和私密链接。
- 表情评论只能从服务端白名单选择，不允许自由文字。
- 食物名称可选，热量和营养数据由识别候选自动填入；用户仍可修正。
- 普通 RGB 图片无法可靠推断精确克重。接口必须支持估算范围、识别警告和不确定状态。
- 训练与饮食保留独立数据模型，只在日历和日时间轴中聚合展示。
- 删除的是重复说明文案，不删除错误、权限、隐私、危险操作和识别不确定性提示。
- 正式 Android 包禁止回退到 debug 签名。

## 官网设计

新建独立 `website/`，不修改旧 `web-prototype/`。

视觉读取：年轻消费级健身产品，冷调运动科技、浅色主背景、强对比单一行动色、真实运动影像和克制的滚动叙事。

设计旋钮：

- `DESIGN_VARIANCE: 8`
- `MOTION_INTENSITY: 7`
- `VISUAL_DENSITY: 4`

页面结构：

1. 单行导航：品牌、产品、训练、饮食、好友、下载。
2. 非对称首屏：短标题、下载按钮、真实运动视觉和手机产品界面。
3. 滚动堆叠功能展示：训练、动作识别、饮食识别、好友动态。
4. 统一日历展示训练与饮食如何形成一天的记录。
5. 图文手册与隐私说明。
6. 下载区：Android APK、Google Play、App Store，未开放渠道显示明确状态。

官网必须支持 `prefers-reduced-motion`，并在 320、375、414、768、1024、1440 宽度验证无水平溢出。

## 好友训练动态

新增不可变训练发布快照，包含：

- 发布者稳定用户 ID
- 来源训练记录 ID
- 训练名称、开始和完成时间
- 时长、训练量、有效组、完成率
- 动作摘要与组数
- 可选的短发布说明
- 创建、更新时间与删除状态

发布后好友可以：

- 点赞或取消点赞
- 从白名单选择表情评论
- 查看聚合数量
- 保存分享中允许复用的训练结构

用户可以删除自己的动态。动态查询只返回本人和已接受好友的内容。

## 饮食识别与历史

饮食页改为：

- 周/月日期导航
- 当日热量与蛋白质摘要
- 餐次时间轴
- 多图片选择、预览、删除和重新上传
- 上传后识别状态：排队、处理中、完成、图片不足、失败
- 自动填充热量、蛋白质、碳水、脂肪和份量候选
- 食物名称可选
- 候选结果可编辑后保存

识别后端使用可配置的 OpenAI 兼容多模态模型接口，生产环境通过环境变量提供 Base URL、模型和密钥。服务未配置时必须返回清晰错误，不生成假营养数字。

## 统一日历

训练记录和饮食记录不合并存储。控制器按日期聚合为日摘要：

- 训练完成、计划或错过状态
- 饮食记录数量与总热量
- 当天时间轴中的训练和餐次事件

## 应用内手册

在“我的”增加“使用指南”，资源内置在 APK：

- 快速开始
- 创建和执行训练计划
- 自由训练与组间休息
- 训练记录和日历
- 动作库与动作识别
- 饮食拍照和营养复核
- 好友搜索、动态和隐私
- AI 与账号设置

每章包含图片、短文字、步骤和可选的功能跳转。首次引导只展示一次。

## 主题系统

把硬编码暖橙色迁移到语义颜色 token。保留已有 5 套概念并增加 5 套，形成 10 套明显不同的方案，其中除暗夜方案外均以浅色背景为主。

正式客户端先提供 3 个可切换主题：冰川钴蓝、森氧绿、钛银竞速红。其余作为后续主题候选，不维护十套独立组件。

## Android 安装与签名

- 国区包名固定为 `com.kilostrength.kilo_strength`。
- 海外包使用 `.global` 后缀。
- release 构建必须提供固定 keystore、alias 和密码。
- 缺少发布密钥时构建直接失败。
- 本地脚本与 Codemagic 使用同一组环境变量。
- 如果旧安装包使用的签名私钥无法找回，用户需最后卸载一次；此后所有版本可覆盖升级。

## 验收标准

- 后端测试覆盖动态权限、发布、删除、点赞和表情评论。
- Flutter 测试覆盖完成训练后的发布入口、好友动态、饮食多图、自动候选、跨日记录、统一日历、手册入口和主题切换。
- `flutter analyze` 与 `flutter test` 通过。
- 官网构建通过，并完成桌面和移动端真实浏览器截图检查。
- Android 版本号递增，产出唯一命名 APK，并报告文件大小和 SHA-256。
- release 签名缺失时不会生成冒充正式版的 debug 签名 APK。

## 已知依赖

- 生产食物识别需要配置兼容的多模态模型服务与对象存储策略。
- 商店下载按钮需要后续填写真实 App Store 和 Google Play 链接。
- 若没有原 APK 的签名私钥，Android 无法绕过平台签名校验直接覆盖旧安装。
