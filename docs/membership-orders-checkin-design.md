# 会员、订单与签到设计决策

## 商业目标

- 目标用户：已经使用形域记录训练、偶尔使用 AI/动作识别的个人健身用户。
- 当前替代方案：用户维持免费使用，或在额度耗尽后直接离开；现有季付/永久方案和本地订单不足以形成可信购买闭环。
- 最小采用路径：免费训练记录 → AI 每日 3 次 → 额度用完显示透明付费说明 → 选择月付/年付 → Apple 系统支付 → 服务端验单 → 会员生效。
- 留存路径：登录后每日可签到一次；累计 7 个不同自然日奖励 15 天会员，领取后进入下一轮 7 天。
- 主要指标：额度耗尽弹窗到系统支付拉起率、支付完成率、7 日签到完成率、付费后 30 日留存。
- 失败成本：客户端自授会员或订单状态不可信会造成收入与权益风险；签到可重复领取会造成会员期限失控。

## 产品约束

- 训练记录核心功能保持免费，会员弹窗只在额度耗尽或明确会员能力入口出现。
- 商品只保留月付、年付；两者均由商店展示本地化价格，不在客户端硬编码实际结算价。
- 服务端是订单、签到和会员期限的唯一可信来源。
- 待支付订单仅在尚未进入不可逆的商店交易前允许取消；完成、取消订单不可再次改写。
- 同一用户同一时间只保留一个同商品待支付订单，防止反复点击产生订单垃圾。
- Apple 支付必须以服务端校验结果为准；测试使用 Sandbox/TestFlight，不伪造成功交易。

## 视觉读取

页面类型：移动端会员商业页；视觉语气：浅色暖橙、年轻、清楚、可信；设计家族：Material 3 的系统性结合 Apple HIG 的清晰层级。中等密度、轻量状态动效，订单通过状态标签和时间线表达，不堆叠营销卡片。

交互预览：`docs/previews/membership-orders-checkin-preview.html`。

## Apple 商品与测试配置

- 在 App Store Connect 的同一“订阅组”中创建两个自动续期订阅：
  - `com.kilostrength.pro.monthly`：1 个月。
  - `com.kilostrength.pro.yearly`：1 年。
- 价格、币种和本地化文案以 App Store Connect / StoreKit 返回值为准；界面中的价格只是商店不可用时的占位文案。
- 服务端 `/etc/kilo/kilo.env` 需配置 `APPLE_SHARED_SECRET` 和 `APPLE_BUNDLE_ID=com.kilostrength.kiloStrength`，密钥不进入 Git 或 Flutter 构建参数。
- 真实交易测试使用 App Store Sandbox 账号或 TestFlight，覆盖成功、用户取消、扣款失败、续期、到期和恢复购买。
