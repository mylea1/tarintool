# 训练界面精简与成长整合

## 范围

保留暖白背景、橙色品牌按钮、五项底部导航和现有训练数据。按用户本次六项要求调整：文案盘点、多色肌群图、全屏计划编辑、合并动作成长、紧凑会员卡、我的订单。

## 文案选择

本轮输出 Markdown/JSON 页面文案清单。文案按来源页面/组件组织，附稳定 ID 和代码位置。用户选择前不批量删除解释文案，也不删除用户填写的训练备注。重构中不再使用的重复标题和与新色阶矛盾的旧描述随组件一起处理。运行时 AI 回答、远端资料和用户输入不能用静态源码清单穷举，必须在清单中明确。按用户最新要求停止修改 HTML；后续使用 `dart run tool/export_ui_copy.dart --no-html` 更新清单。

## 视觉与数据约定

- 原生 Flutter 产品界面，暖白与品牌橙色，布局变动程度 3/10、动效 3/10、密度 5/10。
- 肌群训练量用多段色阶表示绝对有效组数，0 为灰色；蓝、青绿、黄绿、金黄、橙和珊瑚红随组数增加平滑过渡。人体图、进度条和图例必须共用阈值。这些色阶表达数量，不等价于是否过量的结论。
- 恢复值由红、橙、黄、绿到青绿插值。真实 0% 是低恢复红色，只有缺少记录才显示灰色。
- 新建计划使用全屏路由和常规返回，名称与动作编辑复用现有草稿数据；保存写入一次，取消不留下空计划。键盘、Safe Area、动作增删与组数输入均须可用。
- 动作成长默认展示折叠卡，展开才显示趋势。重量和次数必须属于同一个实际完成组，严禁拼接不同组的最大值。日期轴按真实时间间隔，重量 kg 和次数使用独立标尺；机器器械按场地隔离。删除独立最大重量与 PR 部分，保留底层历史记录。
- 月付和年付优先同屏两张紧凑卡，价格和订阅周期读取现有购买模型，大字体可改为紧凑纵向排列。共有权益只展示一次。
- 我的订单在“我的”中直达现有订单页；验证远端异步加载结果能够更新列表，购买与权益规则不变。

## 验收

1. HTML 预览：320、375、414、768、1024、1440 宽度的切页、展开、方案选择、新增组和订单入口，无横向溢出。
2. Flutter：全屏草稿保存/取消、配对重量次数、恢复缺失与 0 区分、动作图折叠/展开、订单路由和紧凑会员卡。
3. 原生截图检查正常与小屏布局；格式化、静态分析和受影响测试。
4. 版本号与源码标识一致；构建 CN Android 包并核验包名、版本、签名及校验和。
5. 仅提交本轮相关文件，GitHub 推送成功后报告提交与 APK 路径。

本次设计主要改善查看训练变化、创建计划和比较订阅方案的任务完成效率。最终验收以 Flutter 实际实现为准，不再制作或修改 HTML。
