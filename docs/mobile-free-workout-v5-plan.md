# KILO 自由训练与动作选择 v5

## 产品判断

- 主页恢复训练概览、训练周、进步摘要和最近记录的原有信息架构，但所有模块只使用真实数据；无数据时在模块内部显示空状态，不退化成单一欢迎页。
- 动作选择属于训练中的高频工具，优先减少查找时间：搜索、部位筛选、图片、器械信息同屏；选择后立即返回训练。
- 自由训练不是计划的变体。添加动作时创建 0 组、休息 0 秒；用户主动添加第一组后再输入重量与次数。
- 每个动作在实时训练卡顶部直接设置休息时间。完成组后按该组覆盖值优先、动作休息其次；均为 0 时不启动休息。
- 自由训练完成页默认勾选“保存为训练计划”，允许修改计划名或取消勾选。保存的实际重量转换为下一次计划重量，历史记录仍保留实际重量。
- 完成组反馈使用顶部短时粒子爆发，不遮挡输入和底部操作；支持系统减少动态效果。

## Reddit 用户证据

- Hevy 用户反复反馈新增或保存 routine 后休息计时被关闭/重置，且训练中才发现，说明休息时间必须在动作上下文可见并可靠保存。
- 用户希望训练中做较大重量/次数修改时直接使用手机输入，追求少点击和直接数字输入。
- Strong 用户认可简洁记录，但持续要求更完整的计时能力，说明计时可靠性比装饰性功能更重要。
- 训练组数不存在统一默认值；固定 3 组会替用户做训练处方决策，自由训练应由用户显式添加。

## 验收标准

1. 首页始终保留概览、训练周、进步、最近记录四个区块；空数据有明确但紧凑的占位与入口。
2. 实时训练动作选择器包含搜索框、部位分类和动作图片；320/375/414 px 无水平溢出。
3. 自由训练新增动作：`sets.isEmpty`、`restSeconds == 0`；新增第一组：重量 0、次数 0、计划重量 null。
4. 自由训练动作卡可设置 0–600 秒休息；0 秒完成组不启动倒计时，非 0 秒同步 Flutter 与 Android 通知。
5. 完成组触发顶部粒子效果，约 800 ms 后自动清理；重复点击取消完成不触发；reduced motion 使用静态反馈。
6. 完成自由训练时默认保存计划，可取消；计划包含本次动作、组数、次数、休息和由实际重量生成的计划重量。
7. DeepSeek 只由后端读取 `DEEPSEEK_API_KEY`，Flutter 和 Git 中不得出现密钥；未配置返回 503，不再返回伪回答。
8. 版本升级并通过 format、analyze、test、Node 语法检查和 Android APK 构建。

## 设计读取

移动端训练记录工具，目标用户在训练中单手高频操作；Material 3、克制紧凑、信息层级清楚。视觉密度 7/10，动效强度 5/10，布局变化 4/10。
