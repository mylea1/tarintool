# 动作识别报告与遮挡恢复 V2

状态：已批准并进入实现。用户已经明确选择合并证据、自然语言评价与暖橙主题，并连续要求执行，因此不再等待额外视觉确认。

## 产品判断

用户不是来查看算法日志，而是要在一组训练结束后尽快完成一个决定：下一组是否需要调整，以及先改哪一件事。结果页的主要衡量指标是“看懂分析并保存到下一组”的完成率；辅助指标是证据图打开率、重新上传率和结果页停留时长。

失败的代价不是少看一张图，而是用户把不可靠的骨骼点当成自己的动作问题，或因重复、机械的报告失去信任。因此这版优先保证证据完整、结论合并和不确定性降级。

## 设计读取

- 页面类型：Flutter 移动端训练结果详情。
- 目标用户：刚结束一组训练、没有动作分析技术背景的普通训练者。
- 视觉语气：暖橙、克制、像训练搭档，不像医疗报告或调试台。
- 设计系统：沿用现有 Material 3 组件、导航、品牌 token 和无障碍契约。
- 视觉密度：5/10。
- 动效强度：2/10，仅保留证据图切换和展开反馈。
- 布局变化：结果区中等改版，不改一级导航。

## 最小路径

1. 先看到一句能执行的总体评价。
2. 在同一证据区域看到所有相关秒数的完整骨骼图。
3. 点击任一图片可按原比例放大，不裁掉人物。
4. 看到下一组只需要优先调整的一到两件事。
5. 点击“保存到下一组”。

## 信息架构

结果页不再按事件重复生成卡片，也不显示“系统看到了什么”“这意味着什么”“下一组这样调整”等报告式标题。

首屏顺序：

1. 动作名称与机位。
2. 一段自然语言教练反馈，时间点直接写进句子。
3. 合并证据区：两列或横向分页，图片使用原始宽高比和 `contain`，角标只显示时间。
4. 一段下一组建议。
5. 单一主动作“保存到下一组”。

同一错误在多个相近时间出现时，只写一次，并把时间合并为“00:00.6、00:04.9 和 00:15.6 附近”。同一时间存在多个问题时，也合并在一段话中。

## 遮挡与证据等级

每个腕点分为三类：

1. `observed`：模型置信度达到阈值，直接用于角度和绘制。
2. `inferred`：腕点不足，但肩、肘可见；利用相邻可信帧中的小臂相对方向、当前上臂方向和稳定肢段比例恢复。没有相邻可信帧时，仅在低置信度原始点仍提供合理方向时用于“方向估计”，端点长度被解剖比例约束。
3. `missing`：没有足够证据，不画腕点，不把该帧用于需要腕点的结论。

推算点只允许支撑肘角和小臂方向等低依赖指标，不能用于握距、手腕姿态或器械接触判断。推算帧的事件置信度必须降低，并在诊断指标中记录；用户端只看到可靠结论，不看到算法术语。

## 引体向上专项

正前或正后机位同时检查：

- 左右肩高度差：使用躯干长度归一化，必须持续多个采样帧才提示。
- 同一时刻左右肘角差：比较肩—肘—腕角；腕点为推算时降低置信度。
- 行程：使用双侧肘角范围和完整伸展—屈曲—伸展周期，不依赖“第几次”。
- 身体侧摆：使用肩中点和髋中点的相对横向位移，只在正面/后面机位判断。

侧面机位不输出左右对称结论。

## 安全边界

- 单目 RGB 只描述画面中的二维轨迹，不诊断伤病、肌肉募集、脚底压力或真实三维关节负荷。
- 阈值用于筛查和下一组提示，不等同于医学或专业教练结论。
- 推算点不能伪装成真实观测点；诊断 JSON 保留来源和数量。
- 证据不足时返回具体缺失条件，不用“没有问题”替代“无法判断”。

## 响应式与无障碍验收

- 320、375、414、768、1024 和 1440 宽度无水平滚动。
- 证据图片不使用 `cover`，人物和骨骼不得被裁掉。
- 200% 文本缩放时，时间角标、按钮和建议不重叠。
- 超长中文评价自然换行，卡片不使用固定高度。
- 所有图片有包含时间的语义标签，点击目标至少 48 dp。
- 加载、空证据、图片失败和分析不足都有可恢复状态。
