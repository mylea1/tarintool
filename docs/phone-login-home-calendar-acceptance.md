# 手机登录与首页日期记录

## 本轮范围

仅修改现有 Flutter App 与 Node 后端。保留五项导航、原账号数据、会员支付和动作识别逻辑。不修改 HTML，不构建 Android，不部署生产服务；测试后提交 GitHub。

## 交互与数据契约

- 登录卡保留密码登录，增加验证码登录与明确注册入口。注册需要验证手机号并设置、确认密码；短信登录只用于已有账号，不以裸手机号完成认证。
- 手机号输入的中国大陆 11 位与 +86 形式指向同一账户。两种登录方式读取同一用户、会员和训练数据，客户端仅持久保存受保护的会话凭据。
- 服务端提供验证码申请、验证注册和验证码登录；密钥、短信签名与模板只从服务端环境配置读取。未配置或发送失败明确报错，不返回测试验证码或模拟成功。
- 验证码由阿里云 PNVS 生成，仅服务端接收后哈希存储、限时、限制错误次数、一次性消费；重发失效旧码，并对手机号与来源限频。新注册不能放开原有仅开发环境使用的无验证注册接口。
- 首页本周日历的训练完成日使用青绿色底色，今天/选择状态另外标识。点击日期仅查看该日真实记录或计划，不启动训练、不发布动态；无数据展示空态，一天多次训练均可查看。
- 日期选中后，下方原肌群区域显示紧凑训练卡片；用户可切回训练量与恢复。训练量、恢复轮切的原有手动停止行为保留。
- 删除用户截图圈选解释文字；购买按钮统一为「购买 · 价格」。保留真实错误反馈、不可购买状态与套餐价格/周期/续订信息。

## 验收重点

1. 服务端隔离测试覆盖注册、密码和验证码登录同一账号、规范化、过期/错误/重放、限频、发送失败与身份冲突。
2. Flutter 测试覆盖登录状态和会话保存、注册字段、验证码冷却与错误、日期选择/回切/详情、小屏和放大文字。
3. 真实 Flutter 渲染检查登录和首页，不用 HTML Demo 代替。
4. 提交前检查差异、静态分析与密钥泄漏；不把模拟供应商测试报告为真实短信已送达。

## 外部配置

用户已确认 SignName「恒创联众」、TemplateCode「100001」、TemplateParam `{"code":"##code##","min":"5"}`。这是号码认证服务 PNVS 的配置，实际发送使用 `dypnsapi.aliyuncs.com` 的 `SendSmsVerifyCode`，不是普通短信服务的 `SendSms`。

明确设置 6 位数字、300 秒有效期、60 秒发送间隔。服务端请求返回验证码，仅用于本地哈希验证，不向 App 或日志输出验证码。访问密钥不得提交 GitHub。源码交付不等于生产后端部署或真实短信联调完成。

参考：[阿里云 SendSmsVerifyCode 文档](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode)。

本轮设计优先缩短注册路径和查询当天训练记录的操作步骤，不改变付费权益范围。
