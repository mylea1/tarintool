# 首页小屏密度与互动肌群图设计说明

## 商业判断

本轮最可能改善的指标是“首页进入训练的完成率”。负责推动该指标的是首屏唯一的橙色“开始/继续今日训练”按钮，以及将周历、肌群和趋势压缩到其后的渐进信息层级。

## 用户与现状

目标用户是在健身房使用 320–375dp Android 手机记录训练的人。他们需要在组间短时间内确认今天练什么并马上开始。当前替代方案是滚动查看偏大的卡片和图标；占屏过高使首屏信息密度低，现有简笔人体图也无法回答“本周到底练到了哪里”。

## 前提挑战

1. 首页是行动入口，不是完整统计报表；详细统计继续留在记录页。
2. 肌群图只能呈现真实完成训练的刺激分布，不描述无法从记录验证的恢复状态。
3. 动作库清理采用明确的禁用器械和业务归组，不再按任意批次删除动作。

## 比较过的方案

- 方案 A：只缩小图标并替换人体图。风险最低，但无法解决卡片层级和首屏滚动问题。
- 方案 B（采用）：按参考图重排为“今日训练主卡 → 紧凑周历 → 肌群/趋势双卡 → AI 入口”，同时引入真实 SVG 和小屏密度 token。
- 方案 C：完整重做导航和首页数据体系。成本高且会改变稳定契约，本轮不采用。

## 设计读取

- 页面类型：移动端健身首页仪表盘
- 目标用户：训练现场、单手操作、小屏 Android 用户
- 视觉语气：暖橙、克制、专业但年轻
- 设计系统：现有 Material 3 与项目暖橙 token
- 设计变化度：5/10
- 动效强度：3/10
- 信息密度：7/10

## 页面结构

1. 54dp 紧凑顶栏：30dp 品牌标识、19sp 标题；图标视觉尺寸 20–22dp，触控区域保持至少 48dp。
2. 今日训练：训练名、主要肌群、预计时长、首个动作图片；一个高优先级橙色按钮和一个低优先级“调整计划”。
3. 本周训练：单卡七天圆点/日期结构，选中日橙色、完成日勾选、安排与完成状态可辨识。
4. 本周肌群：复用 `docs/ai-training-muscle-selector-files.md` 指向的男女正背面 SVG、叠加层和 48×88 点击蒙版。点击具体肌群后高亮 SVG 层并显示名称。
5. 动作趋势：可以选择有历史重量的动作，只和用户自己的同一动作历史比较。
6. AI 定制训练：单行紧凑入口，不与主训练按钮竞争。

## 响应式与安全边界

- 320–374dp：页面水平间距 12dp；双卡使用 `min-width: 0` 等价约束，必要时堆叠；图标只缩视觉尺寸，不缩触控区域。
- 375dp 以上：页面水平间距 14dp；肌群和趋势保持双列。
- 200% 文本：今日卡允许标题两行；按钮保持整行；双卡在不足宽度时转单列，不使用固定高度承载长文案。
- 图片和 SVG 使用明确纵横比，避免加载后布局跳动。

## 动作与器械规则

- 从可选动作库移除设备为波速球、滑雪机、训练锤的动作，相关筛选项同步消失。
- 固定自行车、椭圆机、登阶机归入中文筛选项“有氧”，动作本身仍保留。
- 不修改稳定动作 ID，不影响已有训练记录反序列化；历史记录仍可显示已保存动作。

## 验收

- 首页首屏主 CTA 清楚且无重复主按钮。
- Android 小屏不出现过大的装饰图标、水平溢出或卡片遮挡。
- 肌群卡使用真实 SVG，正背面和肌群点击可交互。
- 指定三类器械及动作不再出现在新建计划/自由训练选择器；三种有氧设备只出现在“有氧”筛选下。
- 320/375/414/768px 与 200% 文本缩放通过浏览器预览和 Flutter widget 测试。
