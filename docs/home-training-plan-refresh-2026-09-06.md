# 主页、今日计划与推荐规则调整（2026-09-06）

## 页面变化

主页移除今日安排，保留周历、人体肌群图、训练组数与恢复切换。今日安排移入独立训练页，合并相关肌群恢复、地点与启动训练入口。个人计划使用紧凑卡片，点击卡片查看详情，选择按钮安排今天，不立即启动训练。

计划封面默认使用 App Logo，点击可选择图片。仅接收不超过 15 MB 的图片，解码缩小后以 PNG/base64 随训练库保存，不依赖临时文件路径。老计划缺少封面字段时正常回退 Logo；用户自定义图片不加入 AI 对话上下文。

记录页训练／饮食／统计共用固定顶部切换区，内容独立滚动，保留各模式图标而不使用选中勾替换。移除统计页重复的好友训练入口。

## 今日推荐的新规则

- 候选来自服务端现有官方计划目录及个人计划，不要求以前练过。官方目录沿用缓存／刷新机制，未来发布的官方计划可直接进入候选。
- 从动作目录的主要肌肉和身体部位字段识别目标部位，不使用计划名称或动作名称猜部位。
- 新增“不练部位”（excludedMuscles），与原来的“减少训练”分开；不练为硬排除，减少仅降优先级。排除针对主要训练肌群，并不承诺复合动作完全没有辅助肌参与。
- 不喜欢／不可用动作、未知动作和空计划不自动推荐。
- 个人计划覆盖胸、背、肩、腿及额外重点肌群后，优先使用个人计划；不练部位从覆盖要求中移除。腿的各子部位在覆盖判断中归为腿。因此不练腿时，个人计划覆盖胸、背、肩即可。计划数量、名称、历史是否练过均不是资格条件。
- 覆盖不足优先官方计划，不把唯一旧个人计划作为默认兜底。个人库完整但当前无合适计划时，可回退官方计划。
- 主要肌群恢复估算低于 60% 时过滤该计划；同候选来源中有近期未练过的合适方案时，优先这些方案。
- 排序综合平均恢复估算、重点肌群、减少肌群、近四周组数和用户期望时长。已有恢复估算模型不变。
- 用户选择的非训练日不自动安排训练；手动安排今天的计划仍须通过偏好、恢复和近期刺激校验。删除旧的“自动承接前七天漏练计划”逻辑。
- 无官方计划或所有候选被过滤时明确显示空状态，可手动查看计划或自由训练。
- 官方目录目前提供动作 ID，未提供每组重量处方；新建官方训练采用 3 组模板且重量为 0，用户自行输入，不伪造固定负重。后续若官方计划提供完整处方，需要扩展 PlanSession 数据契约。

## 实时推荐重量现有规则（算法暂未改动）

本次仅隐藏解释展开项和决策文案，只展示推荐重量。无历史时显示待建立记录，不展示 0 kg 为推荐负重。

五种状态：
1. 建立基线：没有已完成、重量和次数均大于 0 的可比较组。
2. 减少训练量：恢复估算低于 60%，重量不变，建议组数为 max(2, 上次组数-1)。注意上次只有一组时，该旧规则反而给出两组，后续应修订。
3. 保持重量：已有技术评分总分低于 80 或稳定性低于 78，或其他加重条件未满足。
4. 保持重量并补足次数：上次存在低于自身 targetMin 的有效组。
5. 增加重量：至少两次有效训练记录；最近两次纳入判断的所有组 reps >= 各自 targetMax；最近一次所有组的已填 RIR >= 2、已填 RPE <= 8；恢复 >= 60%；已有技术评分不触发阻止条件。以最近一次最大重量为基准，小于 60 kg 加 1 kg，否则加 2.5 kg，同时降低推荐次数区间 2 次。

局限：未填 RIR/RPE 或没有技术评分会放行；未完成组被排除；热身组没有单独过滤；各组重量不必一致；使用历史列表的已有顺序；器械动作仅在当前地点非空时隔离地点；未匹配到肌群时恢复默认 100%。所以旧兜底文案“证据不足以安全加重”不能说明具体哪个条件失败，也不表示已进行个体安全评估。
