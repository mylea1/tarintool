# KILO 动作封面与详情设计

日期：2026-08-05

## 问题与目标

当前动作库使用少量重复插画，动作详情只包含文字备注和外部链接。用户无法在选择动作前快速确认动作，也无法在同一处回看该动作的训练表现。

本轮目标是让用户完成三个连续任务：识别动作、理解动作、回看自己的训练记录。核心指标是动作选择完成率、动作详情查看率和历史记录回访率。

## 商业与用户判断

- 目标用户是训练中需要快速确认动作和重量的力量训练者。
- 当前替代方案是在动作库、视频平台和训练记录之间来回切换。
- 最小可用路径是点击动作封面，直接看到 GIF、训练要点和真实历史。
- 失败成本是选错动作、训练中断，或记录存在但用户无法用于渐进超负荷决策。

## 设计方案

采用全高底部详情页，保留当前动作库的信息架构与 Material 3 视觉语言。

1. 动作列表使用数据集 JPG 作为静态封面，图片和整行都可打开详情。
2. 详情顶部使用对应 GIF 自动演示，并保留动作中文名、英文名、器械和肌群。
3. 内容分为“概览 / 教学 / 记录”三个同级标签。
4. 概览展示训练次数、最重重量、估算 1RM 和最近表现，没有历史时给出明确空状态。
5. 教学展示数据集中文分步说明和现有 KILO 动作提示。
6. 记录只读取 AppController 中真实 WorkoutRecord，按日期展示完成组、重量、次数与 RPE。
7. 原有动作库、本次训练、计划三种备注继续保留在概览中，不改变数据契约。

## 素材策略

数据集包含 1,324 组 JPG 与 GIF。本轮按语义匹配当前 32 个动作，只复制实际引用的 64 个文件到 `mobile/assets/exercises/reference/`。运行时不解析 17 MB JSON，也不把完整素材库打入 APK。

## 交互与边界

- GIF 加载失败时显示静态封面，再失败时显示健身图标。
- 详情内容可滚动，320-1440 px 宽度不产生水平滚动。
- 标签、按钮和封面触控目标不小于 44 px。
- 动画只来自 GIF 和 Material 状态过渡，系统减少动态效果时不增加额外动效。
- 超长动作名、无记录、旧记录缺少逐组快照、零重量自重动作均有可读降级。

## 验收标准

- 当前 32 个动作都有独立 JPG 封面和对应 GIF。
- 点击动作封面或列表行可打开动作详情。
- 详情能切换概览、教学、记录，并展示对应真实内容。
- 原有加入训练、备注和教学链接能力不回归。
- Flutter analyze、test、debug APK 构建通过。
