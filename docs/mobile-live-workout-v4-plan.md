# KILO 移动端训练流程 v4

## 商业与任务判断

- 目标用户：在健身房内单手、短时、高频操作的力量训练用户。
- 当前替代方式：先做计划再训练，或临时转用备忘录，训练结束后补录。
- 最小可用路径：点击“自由训练”立即开始计时，训练中添加动作、组数和实际重量，结束后自动形成真实记录。
- 核心指标：自由训练启动率、首个动作添加完成率、完整训练保存率。
- 失败成本：用户被迫提前规划或二次录入，直接放弃记录功能。

## 范围与验收

1. 计划编辑使用完整路由页面和独立草稿；返回不保存，保存才提交。紧凑字段显示组别类型、计划重量 kg、次数、休息秒数。
2. 训练页提供“自由训练”。空训练仍开始总计时，页面显示“添加第一个动作”；训练中可添加动作和组数，不重置已用时。
3. 训练实际重量字段始终显示 `kg`，记录保存实际重量；自由训练的计划重量保持为空。
4. Android 使用真实前台服务维护训练通知。通知每秒显示动态剩余休息和总训练时长，公开锁屏可见，并可跳过休息。不得使用全屏闹钟权限。
5. 删除所有可见演示数据：预置用户计划、历史、排程、进步、AI 对话、已选视频和识别结果。动作目录与官方单日计划属于静态产品内容，保留。
6. 未配置 AI/识别服务时展示空状态或服务未配置，不伪造回答与识别报告。
7. 字体层级整体缩小一级；输入框采用紧凑密度。次要命令优先使用带 tooltip/semantic label 的 Material 图标，主动作保留文字。
8. 空数据、长文案、320/375/414 px 宽度下无横向溢出，触控目标不小于 44 px。

## Android 约束

- 前台服务通知频道使用新 ID，避免 One UI 缓存旧频道设置。
- Android 13+ 请求通知权限；Android 14+ 声明适当的 foreground service 类型。
- One UI 是否在锁屏展示具体内容仍受系统“锁屏通知/显示内容”和电池策略控制，应用不能绕过用户隐私设置。
