# 形域：功能与使用指南 / App Store 素材任务交接

日期：2026-09-06。核对基线：`fd00ce9`，Flutter `mobile/`，版本 `1.0.41+43`。
本文件根据当前代码、近期变更文档整理；“有实现”不代表已在 iOS 真机验证。优先级：目标 iOS 构建实际表现 > 当前代码 > 本指南 > 旧 README / 原型。本文不包含账号密码、API 密钥或用户私密数据。

## 1. 本次任务与执行边界

用户要求：整理软件全部功能及使用方法，供新任务策划用于 **Apple App Store 的预览视频和产品截图**。新任务使用 **gpt-6-astra / medium**。

新任务本轮只阅读、核对官方规范、给出规划与分镜，等待用户确认。不要开始录屏、截图、生成媒体、搭建演示数据、修改产品代码、打包、发布动态或上传 App Store。必要的设备和服务条件以待确认项列出；不要因为缺少设备而放弃策划。

之前讨论过 AI 真人运动宣传片，那是普通营销方向，不是此次 App Store 任务的默认方案。不要直接复用旧简报的 45–60 秒真人片。商业主线应聚焦“AI 结合训练与记录”，让真实操作解释价值；基础训练记录同样重要，不要把全部画面变成会员推销。

## 2. 产品与当前导航

中文品牌名：**形域**。定位：把计划、训练现场记录、动作教学、AI 教练、训练复盘与饮食管理连接起来的力量训练应用。

- 底部：主页、记录、动作、AI、我的。
- 右侧独立圆形“训练”按钮：展开“计划”和“新建训练”；存在可恢复训练时显示“返回训练”。
- 主页右上角：好友入口；统计中重复的好友入口已移除。
- “记录”页：训练 / 饮食 / 统计，切换栏保持位置稳定。
- 两种主题：浅色与深色，暖橙品牌色；Logo、会员卡、训练卡随主题变化。
- 主页保留周训练日历、人体肌肉图、训练组数与恢复状态。每日计划安排已迁移到训练计划页，不再用巨大的付费建议占据主页。

## 3. 功能与操作路径

### 3.1 注册、登录、首次资料

手机号注册：输入手机号 → 设置及确认密码 → 最下方验证码输入框右侧发送验证码 → 输入验证码注册。新密码最多 10 位，具体最小长度和服务端校验以当前界面为准；不要在视频中暴露密码或验证码。登录方式受平台与渠道约束：Android 手机号；国区 iOS 手机号 / Apple；海外 iOS Apple / Google。入口存在不等于 OAuth 供应商已配置。

首次进入填写训练资料与偏好：基础身体资料、训练目标与经验、时间安排、次数区间、器械/地点相关资料、重点或不练肌群、不喜欢动作。支持跳过，并保存跳过状态；之后从“我的 → 训练资料”补充或编辑。首次流程不再展示“无法完成的动作”“需要热身组”；编辑资料时仍可配置。臀与腿的选择已拆分，避免把只练臀理解为练全部腿部。未填写字段以简短提示呈现。

个人资料可改头像、用户名，公开身份使用十位数字 ID；手机号搜索需目标账号具备对应已验证手机号，不能声称所有 Apple 登录用户自动绑定手机号。

### 3.2 主页与恢复

查看本周训练 → 点击日期查看当天训练 → 打开品牌记录卡看详情。人体图支持正/背面及肌群选择；训练组数与恢复两种模式用于了解训练分布和恢复估算。恢复是基于记录的估算，不是生理检测或医学结论。

进入某肌群或指标可继续查看对应记录/趋势。没有资料或历史时使用真实空状态，不造出恢复与进步结果。

### 3.3 今日安排与官方计划

训练圆形按钮 → 计划 → 查看今日安排、官方计划、个人计划。

推荐从动作本身的主要肌群识别部位，不根据计划标题猜测。结合用户训练日、训练偏好、不练部位、近期刺激、训练量与恢复估算：个人计划覆盖不足时优先官方计划；覆盖所需肌群后优先个人计划。恢复低于阈值的候选会过滤，没有合适计划允许空状态和手动选择。不得宣传为保证安全或保证效果的处方。

“使用官方计划” → 选择计划 → 详情可“使用此计划”或“开始训练”；使用后关闭相关弹窗。官方目录内容来自服务端；当前不应承诺未来尚未制作的官方课程。目录未提供负重处方时，重量需要用户设置。

### 3.4 个人计划与文件夹

新建计划 → 命名 → 添加动作 → 配置组数、组类型、计划重量、次数/范围、休息 → 保存。可查看、编辑、重命名、删除、排序、替换动作及设置超级组等。

文件夹采用展开/收缩列表，可创建和删除；允许计划不归入文件夹。训练结束保存为计划时可选择文件夹，不选则独立存放。

计划封面默认主题对应 Logo；点击封面可上传自己的图片。首次进入对应计划场景短暂提示约两秒“点击可更换训练封面”。避免为截图保留长期教程遮罩。

### 3.5 开始训练、逐组记录与计时

训练 → 新建训练，或计划详情 → 开始训练。进入训练后由用户手动开始总计时；不要沿用旧文档“点击计划立即计时”。可切换页面再返回训练，继续同一状态。

添加动作 → 填实际重量与次数 → 选择组类型 / 记录强度 → 勾选完成。可见上次真实训练数据、当前组、绿色完成反馈与组间休息。支持暂停、继续、休息设置及跳过、添加或删除组/动作、排序、替换、批量编辑、杠片计算器、超级组、动作备注与逐组备注。

计划重量与实际重量分开保存；训练改动不直接覆盖原计划。上次备注只出现在历史备注区域，不自动重复填入当前备注。上次数据缺失时显示缺失，不伪造历史。

推荐重量目前只展示结果，解释展开项已隐藏。其规则依赖有效历史组、次数目标、已填 RPE/RIR、恢复及已有技术评分；不要展示为实时测力、自动读取器械、必然加重或已做个体安全评估。

### 3.6 训练内 AI：本次宣传重点

训练中的圆形 AI 按钮支持快速按住拖动；点按展开当前动作与“其他”选项。选择动作会进入围绕该动作的聊天，不是普通器械详情。

动作对话含该动作 GIF 与教学，可询问“上一组很吃力，下一组怎么选重量？”“有没有这个动作的教学视频？”；输入区在底部，回答流式呈现，可停止。选择“其他”询问训练、休息、恢复或饮食问题。教学视频搜索优先抖音；不要把搜索链接宣传为平台视频已获得授权或已在应用内播放。

请求结合当前训练快照、选中动作、资料和相关历史；界面与返回内容受服务/额度影响。结构化 AI 计划或调整需用户查看/确认，不宣传 AI 已静默修改完成组或自动执行。适合拍摄“完成上一组 → 选中同动作 → 描述感受 → 看到流式建议 → 回到训练”的闭环。

### 3.7 完成训练与品牌记录卡

结束训练 → 保存真实组数据，可选择保存为计划及文件夹 → 显示形域品牌卡 → 可分享到动态。

当前卡片是连续品牌主画面：左侧较小的动作缩略图、名称、组数、逐组重量次数，右侧留出 Logo / 图片位置；时间、容量、有效组放在底部小字角落。品牌文案为“形域”；自定义计划名原样保留；未命名训练使用日期与时间，不加“自由训练”前缀。

首页训练日历与记录列表复用此样式。记录详情顶部同款品牌卡以总容量、完成组、时长为内容，下方继续展示动作和详细组数据/备注。互动位于卡片外；当前完成页主分享入口是“分享到动态”，不沿用旧“分享卡片”按钮。

### 3.8 历史、日历与统计

记录 → 训练：按日期看历史、打开详情，支持补录及已有记录管理。记录详情显示动作、实际组数据、计划值与差异（有数据时）、完成状态、休息及私密备注。统一日历可串联训练与饮食时间线。

记录 → 统计：时间范围、训练天数、有效组、容量、肌群分布、时长、PR 和关注动作趋势；高级分析按会员权限显示。关注动作选择器带图片与名称，一次看一个动作的一项重量或次数指标，禁止把重量和次数画成同图双线。可定位对应原记录；自重动作按适用指标显示。

我的 → 训练进步：按自然周查看真实工作组与长期变化，保留原记录回溯。缺失历史或不完整周期不伪装成完整进步。

### 3.9 动作库与教学

动作 → 搜索 / 肌群分类 / 器械筛选 → 动作图片卡 → 详情 GIF、中文教学、个人备注与教学链接、历史表现。可切换动作名称语言。底层完整数据集保留 1,324 个动作资源，当前默认展示人工筛选目录；不要宣传默认可浏览 1,324 个动作，除非演示版本核实。

### 3.10 AI 独立页与动作视频分析

AI → 问答：新建、切换、删除会话，加入训练摘要，流式对话，服务/授权设置与自定义 Skill（每账号最多 3 个，可启用/关闭）。适合用一份已有训练总结解释用户下一步，而不是空白聊天页。

AI → 动作识别：选择动作/视频与机位 → 必要时裁剪 → 上传分析 → 报告。按视频秒数定位事件，查看骨骼证据与提示，可选完整骨骼视频。文件选择与服务状态有取消/重试反馈。使用实际可分析的合法素材，不编造评分或报告；不要承诺全动作自动识别、百分百准确或纠正伤病。

### 3.11 饮食、饮水与体重

记录 → 饮食：按日期记录早餐/午餐/晚餐/加餐、饮水、体重。餐食照片可多张输入（现有流程最多八张），识别候选营养值需确认或手动编辑；展示热量、蛋白质、碳水、脂肪及饮水概览。AI 今日饮食建议和训练×饮食分析依赖会员及服务。

体重详情支持趋势、查看/编辑/删除原始测量；按每日最后一条测量和真实时间绘图，缺测不冒充实测。适合作为补充截图，不抢占训练与 AI 主叙事。

### 3.12 好友、分享与互动

主页右上角 → 好友训练：动态 / 好友 / 添加；搜索身份信息、添加好友；分享自己的计划，好友查看动作图片与逐组数据，保存后显示“已保存”。训练完成可发动态，好友点赞及限定表情互动。

公开快照不带训练私密备注和体重等信息。制作阶段只使用获准演示账号；不要误发真实好友动态。好友功能需网络、登录和服务端支持。

### 3.13 我的、会员与设置

我的：紧凑头像/用户名/公开 ID，独立主题适配会员卡，会员状态及有效期、训练资产、资料、进步、统一日历、指南、订单、主题、动作语言、锁屏实时活动、隐私与 AI 授权、关于等入口。

会员能力包括受权益控制的 AI、识别、深度统计、饮食建议及云同步等。具体免费额度、试用、价格、套餐、可购地区以生产服务端和 App Store 商品为准，不把源码枚举或测试账号永久权益当商品承诺。存在兑换码与管理员工具；管理员的创建账号/开会员/生成兑换码不作为普通用户卖点。

Android 前台训练通知和 iOS Live Activity 为平台能力，需在目标平台构建验证。Apple Watch 当前发布范围暂时停用，不拍摄、不宣传。签到已取消，不列入现有卖点。

## 4. 建议演示使用方案（尚未执行）

主流程：有近期历史的演示账号 → 主页肌群恢复 → 训练计划 → 手动开始计时 → 完成一组 → 训练内 AI 询问该动作 → 流式回答 → 结束训练品牌卡 → 日历/趋势复盘。

建议固定一份“上肢力量”演示计划，使用应用目录里真实存在的卧推/划船/推举类动作 ID；3–4 个动作、每动作约 3 组。提前准备多次一致且合理的历史，便于展示上次数据和趋势。演示数据只用于实际应用渲染，不把手绘 UI 或合成回答冒充真实功能。

补充场景：动作 GIF、AI 视频分析、饮食记录、好友保存计划。先选可稳定成功的流程，不把全部功能挤进一个短片。

免费体验和 PRO 体验各有截图候选，付费内容保留实际 PRO 标识；不隐去付费事实，也不把锁定卡当主要画面。建议一套主主题贯穿视频，另一主题用独立截图补充。

## 5. App Store 素材原则与官方资料

2026-09-06 检索的 Apple 官方说明：App Preview 以设备上捕获的应用功能和 UI 画面为主体；每种语言最多三个预览，每个最长 30 秒。来源：[App Previews](https://developer.apple.com/app-store/app-previews/)。因此首版建议规划约 30 秒的真实应用操作预览，普通 AI 真人广告另立方案。

新任务应在方案中核对完整最新版规范，再确定时长下限、分辨率、编码、帧率、音频、文件大小、海报帧、各设备槽位与本地化要求。不要把截图尺寸直接当视频尺寸。官方入口：

- [截图规范](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)
- [上传 App 预览和截屏](https://developer.apple.com/help/app-store-connect/manage-app-information/upload-app-previews-and-screenshots/)
- [App 预览说明](https://developer.apple.com/app-store/app-previews/)

本地 Windows Android APK 可用于流程预演，不能换个状态栏就当作 iOS 原生采集素材。需要确认与本版本一致的 iPhone 构建、iOS 设备或 macOS 模拟器/录制环境。若只有 Android/Flutter Web，规划中明确“预演素材”和“App Store 最终素材”的区别，不声称已具备 iOS 正式录制条件。

## 6. 新任务首轮必须交付的规划

1. 产品理解：核心用户、卖点排序，哪些功能需要 PRO，哪些应排除或待真机核实。
2. 一条 App Preview 分镜表：时间、页面、具体点击操作、画面变化、字幕、预期服务响应、素材条件。
3. 一套建议 6–8 张截图的排序：每张一句价值标题、真实页面、要显示的数据、主题与排版；数量为策划建议，最终按官方支持范围确定。
4. 录制准备清单：目标 iPhone/语言/主题、iOS 版本、账号权益、训练历史、合法视频/图片、网络服务与隐私处理。
5. 执行工具方案：可用设备/模拟器、录屏截图方式、文件保存位置及命名；区分目前已确认与待用户提供的条件。
6. 输出规格及验收：UI 真实、可读、无溢出，镜头操作连贯，字幕不过度遮挡关键数据，商品权益准确，素材满足选定设备槽位。
7. 最后列少量需要用户确认的方向，明确停在规划阶段。用户未确认前不采集、不生成、不上传。

业务判断：前三张截图及开头镜头优先解释“记录上一组后，AI 如何帮助理解下一组”，争取提升产品页到下载的转化；用真实训练记录支撑 AI 价值。
